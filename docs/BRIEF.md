# 핵심 맥락

## 무엇을 하는 사업인가

한국과학창의재단 발주, 팀모노리스·업스테이지·한국컴퓨터교육학회 컨소시엄의 **2026 한국형-AI 기반 교사개발자 양성 과정**. 교사가 학교 문제를 정의하고 AI 도구를 만들어 검증·개선하는 것이 목적이다. 단순 플랫폼 사용법 교육만으로 끝내지 않는다.

사업기간·목표 인원·총사업비·교육 운영 예산은 비공개 협약 및 승인 예산에서 확인한다. 총사업비와 교육 운영 예산을 혼동하지 않는다.

흐름: 기반 집합연수 → 기업 탐방·기술 세션 → 온라인 예선·팀 제작 → 본선 해커톤 → 이수·성과·결과보고·정산. 집합 15차시와 본선 8차시, 예선 12차시 등의 표현이 자료에 공존한다. 인정 시수와 이수조건은 최신 재단 승인·LMS 기준으로 확정한다.

## 누가 무엇을 결정하는가

| 역할 | 담당 확인 | 후임자가 연결할 일 |
|---|---|---|
| 운영 총괄·컨펌 | 운영 총괄에게 확인 | 일정·공문·모집·CS·예약·대외 문안 |
| 사업 책임·콘텐츠 방향 | 운영 총괄에게 확인 | 사업 범위·교육 방향·플랫폼 정책 |
| 기존 운영·AX 담당 | 운영 총괄에게 확인 | 로컬 자동화·기존 자료·이관 |
| 정산·행정 | 운영 총괄에게 확인 | 지출 주체·증빙·승인 예산 |
| 재단·PMS 중계 | 운영 총괄에게 확인 | 제출 경로·보고 이력 |
| 학회 협의 | 운영 총괄에게 확인 | 모집·장소·평가·학회 인력 |
| 업스테이지 실무 | 운영 총괄에게 확인 | 기업 세션·교육설계·개발자 멘토 |
| 강의 | 운영 총괄에게 확인 | 차시 자료·강사 배치 |

현재 역할·연락처는 사내 채널에서 재확인한다. 개인 전화번호는 이 저장소에 복제하지 않는다.

## 교육에서 유지할 핵심

- 코들: 수업 운영·활동지·기록. 짓다: 도구 제작·갤러리·팀 작업. Solar: 제작된 도구 내부 AI 연동이라는 사업 원칙. 바이브코딩 엔진과 결과물의 LLM은 구분한다.
- 트랙 A: 파이썬 자동채점 + 정답 대신 힌트. 트랙 B: 소크룸의 주제 기반 유도 질문형 대화 튜터. 초기 문서의 일반 RAG 챗봇 설명을 그대로 재사용하지 않는다.
- 서울과 부산 2·6차시는 개정 전후가 다르다. 부산은 문제 후보 선정 → 기획서 → 안전성 검증 → 제작 흐름을 강화했다.
- 계정·비용의 지속성, 수준 차이, 학교 배포·현장 적용이 주요 개선 과제였다. 만족도 분석은 개선의 입력이며 인과관계를 입증하는 자료는 아니다.
