# 집합연수 15시간 커리큘럼

## 설계 목표와 시수

교사가 학교 문제를 설명하고 → 학생/교사 사용 흐름을 기획하고 → AI로 작동 도구를 만들고 → 정상·실패 상황을 시험하고 → 수업 적용 계획을 설명하도록 한다.

아래는 기존 15시간 계획과 서울/부산 교안 개정 내용을 **후임자가 재사용하도록 재구성한 수업안**이다. 모든 회차에서 이 시간표 그대로 실행했다는 실적 기록이 아니다. 1~11은 **수업 블록 번호**이며 1시간짜리 공식 차시 11개라는 뜻이 아니다. 1일차 480분, 2일차 420분 = 900분. 등록·식사·폐회는 별도다. 실제 휴식·이동시간의 인정 여부는 운영 승인표와 맞춘다.

## 도구와 역할

| 도구 | 수업에서 하는 일 |
|---|---|
| 코들 | 목표 안내·활동지·보드·제출 기록·동료 피드백 |
| Colab | 1일차 API 호출·문서 데이터화·보조 agent 실습 |
| Solar / Document AI | 모델 응답·문서 구조화·정보 추출 |
| 짓다 | 2일차 및 예선·본선의 도구 제작·수정·전시 |

바이브코딩으로 코드를 만드는 도구와 제작물 안에서 응답하는 모델을 구분한다. 기존 사업 원칙은 제작물 내부의 Solar 연동이다. API 키를 프롬프트·공개 화면·학생 코드에 넣지 않는다. 현재 제품 기능이나 API 버전은 강의 전 테스트한다.

### 2블록 진행표 — 부산 개정 자료에 근거한 60분

도입 3 → A/B 사례 시연 10 → 문제 선정 기준 6 → 문제 카드 예시 6 → 후보 3개 작성 13 → 짝 검토·하나 선택 9 → 사례 피드백 9 → 정리 4분.

문제 선정 질문은 ‘자주 일어나는가? 지금 어떻게 처리하는가? 개선됐는지 확인할 수 있는가?’다. ‘AI 챗봇 만들기’는 해결할 문제가 아니다. 서울 초기안은 문제·기능·AI 요청문을 바로 만드는 구조였고, 부산 개정안은 문제 선정을 먼저 분리했다.

### 3~5블록 강사의 준비와 연결

- 3블록: 경험 나눔 8 / 원리 20 / 응답 비교 17 / 환경 점검 10 / 정리 5분. 특정 모델이 항상 더 우수하다는 결론을 유도하지 말고 같은 입력·조건에서 확인한다.
- 4블록: 개요 7 / 구조화 실습 18 / 정보 추출 17 / 개인 자료 적용 10 / 저장·정리 8분. 표·수식·잘못 읽은 항목을 원문과 확인한다. 샘플 문서와 저장 경로를 제공한다.
- 5블록: 완성 예시 5 / 단독 호출·역할 지시 20 / 추출 자료 연결 23 / 테스트 8 / 공유 4분. 자료를 넣는다고 그 범위 안에서만 답하는 것이 보장되지는 않는다. 자료에 없는 질문에서 ‘모름’과 출처 확인을 시험한다.
- API나 계정 문제가 해결되지 않으면 캡처·준비된 응답으로 흐름을 학습하게 하고 실제 호출 검증을 별도 미완료로 남긴다.

### 6블록 90분 진행표 — 편집 제안

| 활동 | 분 | 강사가 확인할 것 |
|---|---:|---|
| 앞 차시 문제 카드 확인 | 10 | 대상과 어려움이 구체적인가 |
| 4요소 사례 설명 | 15 | 교사 화면과 학생 화면을 구분하는가 |
| 자기 도구의 네 영역 작성 | 25 | 입력·수행·확인·결과가 이어지는가 |
| 최소 기능과 하지 않을 일 결정 | 10 | 이번에 만들지 않을 기능 2개 이상 |
| 동료가 사용 흐름을 따라 읽기 | 20 | 설명 없이도 시작과 끝을 이해하는가 |
| 수정·제출 | 10 | 피드백 반영 이유가 있는가 |

### 7블록 90분 진행표 — 활동 순서는 기존 교안, 시간은 편집 제안

안전 필요성 8 / 유해성 분류와 이유 10 / 규칙 원리 10 / 규칙 작성 15 / 적용 전후 테스트 20 / 조별 공유 5 / 다른 조 규칙 시험 15 / 보완 7분.

규칙 세 가지: ① 무엇을 도울지 ② 하지 않을 일과 대안 ③ 모를 때 답변과 후속 행동. 정상 질문을 모두 차단하는 규칙도 실패다. 실제 학생 개인정보 대신 가상 사례로 시험한다.

## 2일차 — 트랙별 제작·검증·발표, 420분

| 블록 | 분 | 진행 순서(분) — 편집 제안 | 제출물 |
|---|---:|---|---|
| 8. 도구 만들기 | 120 | 기획 확인 10 → 핵심 흐름 제작 70 → 동료 정상 사용 25 → 저장 15 | 입력에서 결과까지 작동하는 최소 도구 |
| 9. 안전성 점검 | 60 | 점검법 10 → 정상/실패 입력 25 → 수정 15 → 같은 입력 재검증 10 | 실패·수정·재검증표 |
| 10. 학교 맥락 반영·시연 준비 | 120 | 학년/단원/사용시간 구체화 15 → 기능 조정 55 → 사용법·시연 준비 30 → 동료 점검 20 | 수정 도구·3분 사용법·시연 순서 |
| 11. 동료 평가·발표 | 120 | 교환 사용 40 → 피드백 정리 20 → 개선 20 → 선정 사례 발표 30 → 총평·회고 10 | 피드백·개선 기록·학교 적용 계획 |

부산 실제 시간표의 10블록은 90분으로 정리되어 있다. 위 120분 표를 부산 실제 실적으로 보고하지 않는다. 서울/부산의 실제 담당 구간 차이는 과거 보고용 원고에 따로 존재한다.

## 트랙별로 무엇이 달라지는가

| | A: 파이썬 자동채점·힌트 | B: 소크라테스식 대화 튜터 |
|---|---|---|
| 교사 입력 | 문제·조건·테스트·힌트 정책 | 주제·난이도·질문 방향·평가 기준 |
| 학생 수행 | 코드 제출·피드백 확인·재제출 | 답변·근거·예시를 담은 대화 |
| AI 역할 | 정답 코드 대신 오류 원인과 다음 시도 힌트 | 결론 대신 사고를 돕는 후속 질문 |
| 모니터링 | 시도·오류 유형·도움이 필요한 학생 | 대화 과정·정체·평가 근거 |
| 핵심 검증 | 정답/오답/빈 입력 처리, 정답 유출 | 같은 질문 반복·주제 이탈·근거 없는 점수 |

B는 단순 ‘자료를 넣고 답을 검색하는 Q&A’가 아니다. 5블록의 자료 기반 agent 실습과 B트랙 최종 도구를 같은 것으로 안내하지 않는다.

## 시간표를 바로 배치하는 방법

표준 서울형: Day1 10~12시 블록1·2 / 점심12~13시 / 13~16시 블록3·4·5 / 16~19시 블록6·7. Day2 09~12시 블록8·9 / 점심12~13시 / 13~17시 블록10·11.

출퇴근형 기존 초안: Day1 09:10~12:10 블록1·2·3 / 점심12:10~13:00 / 13~15시 블록4·5 / 15~18시 블록6·7. Day2 09~12시 블록8·9 / 점심12~12:50 / 12:50~16:50 블록10·11 / 폐회16:50~17:00.

두 표 모두 수업 슬롯 900분이다. 휴식·이동을 넣으면 실제 교수학습 시간이 줄어든다. 승인된 인정시수에 맞춰 장소 종료·식사·강사 이동까지 재계산한다. 6·7블록을 분반 교차할 때는 기획서가 없는 반에 사용할 임시 사례를 준비한다.

활동지는 [WORKSHEETS](WORKSHEETS.md), 완성 예시는 [WORKED_EXAMPLE](WORKED_EXAMPLE.md)에 있다. 근거: 기존 마스터 스케줄·1일차3~5 운영안·9/11 개정 내용 조사. 강사 실명·외부 자료 ID 없이 교육 내용 자체를 재구성했다.
