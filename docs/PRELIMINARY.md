# 예선 — 온라인 12시간, 9/7~10/11

## 무엇을 완성하는 기간인가

팀이 학교 문제 하나를 정하고 작동 도구를 만든 뒤, 다른 사람이 사용해 본 결과로 개선한다. 예선에서 남길 핵심은 **작동 결과물 + 1쪽 설계서 + 발표자료**다. 예선 합격/탈락 기준·본선 진출 인원은 보유 자료에서 확정하지 못했으므로, 제출만 하면 진출한다고 약속하지 않는다.

기록상 예선은 짓다를 공통 제작 환경으로 사용한다. 4인 팀, 신청한 팀의 화상 멘토링 최대 2회, 세 가지 제출물은 **기존 기획 초안**이다. 아래 시간 배분·주별 점검·운영 대응은 **편집 제안**이며 바로 수정해 쓸 수 있다. 온라인 12시간은 제작 활동량 설계로, 12시간의 실시간 강의나 인증된 이수 시수로 단정하지 않는다.

## 12시간 활동 설계

| 단계 | 권장 시기 | 시간 | 팀 활동 | 제출·통과 기준 |
|---|---|---:|---|---|
| 문제·팀 정리 | 1주 | 2h | 희망 동료/주제로 팀 구성, 대상·문제·현재 처리 확인 | 문제 카드·팀 연락 창구·한 줄 목표 |
| 설계·작업 분담 | 2주 전반 | 2h | 최소 흐름, 네 영역, 할 일/제외 기능, AI 요청문 작성 | 1쪽 설계서·역할·프로젝트 공간 |
| 핵심 도구 제작 | 2~3주 | 3h | 입력→AI 처리→출력→기록 구현, 중간 저장 | 정상 사용 한 바퀴·접근 가능한 링크 |
| 안전·품질 검증 | 3주 | 2h | 빈 입력·잘못된 답·주제 이탈·정답 요구를 시험, 수정 | 실패 입력·전후 결과·잔여 문제 |
| 사용자 테스트·개선 | 4주 | 2h | 동료 또는 허용된 대상이 사용, 막힌 곳 개선 | 피드백과 실제 반영 1건 이상 |
| 제출·발표 준비 | 5주 | 1h | 링크·설계서·시연·학교 적용 계획 정리 | 최종 3종과 부스 표시 정보 |
| 합계 | | **12h** | | |

멘토링은 필요한 단계의 작업시간 안에 배치하는 제안이다. 공식 출석·인정시간 산정과 별개이며 실제 팀별 활동 기록을 남긴다.

## 현재 시점에서 인계받는 첫날

정리 기준일 9/22는 계획상 3주차다. 이미 지난 1~2주를 다시 공지하지 말고 다음 순서로 재개한다.

1. 팀별로 **팀원/연락 창구·프로젝트 링크·완료 단계·막힌 문제·본선 참석 기수** 다섯 항목을 받는다.
2. A그룹(아직 문제/팀 없음), B그룹(핵심 흐름 미완성), C그룹(테스트/개선 가능)으로 나눈다. 이는 운영 지원 분류이며 평가 등급이 아니다.
3. A는 문제 카드와 최소 기능을 먼저 정하고, B는 핵심 흐름 1개만 복구하고, C는 사용자 테스트로 보낸다.
4. 계정 만료·API 잔액·팀 편집권·프로젝트 공개/저장을 확인한다. 기능 추가보다 접근 복구를 먼저 한다.
5. 10/11까지 남은 팀별 제출 계획을 합의한다. 결원·지연팀의 예외 처리는 운영 총괄에게 올린다.

[진도표 CSV](../templates/preliminary-tracker.csv)를 복사해 팀별 상태를 관리한다. 실제 이름·내부 링크를 채운 표는 회사 비공개 보관처에 둔다.

## 멘토링 운영

- 신청 전: 결과물 링크, 현재 입력과 화면, 기대한 동작, 실제 동작, 질문 1~2개를 제출.
- 상담 예시 30분(편집 제안): 문제 재현5 → 원인/우선순위10 → 최소 수정 방향10 → 팀의 다음 행동/확인법5.
- 상담 후: 멘토가 대신 완성하지 않고 팀이 수정하며, 같은 입력으로 개선 전후를 비교.
- 운영진은 일정·접속·제출 문의, 제작 지원자는 짓다/구현 문의, AI 기술 지원자는 API/응답 품질 문의를 맡도록 배정. 실명 담당과 응답 가능 시간은 실제 공지에 채운다.
- 원안은 요청 팀만 최대 2회 화상 상담이다. 정원·예약 회차는 실제 멘토 확보 후 확정하며 모든 팀에 자동으로 2회를 배정한 것으로 쓰지 않는다.

## 제출 수합

| 제출물 | 필수 내용 | 운영진 확인 |
|---|---|---|
| 작동 결과물 | 사용 링크·대상 사용자·테스트 접근 방법 | 다른 계정/참가자 권한에서 사용 가능한가 |
| 설계서 | 문제·사용자·핵심 흐름·AI 역할·안전 규칙·제외 기능 | 도구와 설명이 일치하는가 |
| 발표자료 | 문제·시연·피드백·개선·학교 적용 계획 | 실제 화면/기록이 주장과 맞는가 |
| 본선 준비 정보 | 팀 표시명·부스명·기기·전원·상담 질문 | 현장 배치와 상담에 필요한가 |

공식 마감 시각은 확인되지 않았다. ‘10/11 23:59’ 같은 시각을 임의로 확정하지 말고 **10/11 [마감 시각 확인] KST**로 초안을 작성한다. 평가할 버전과 마감 후 수정 가능 범위를 같이 공지한다.

## 운영자가 놓치기 쉬운 것

- 튜토리얼에서 만든 프로젝트가 본 행사로 자동 넘어간다고 가정하지 않는다. 이전 방식과 저장 상태를 실제 확인한다.
- 학생 적용이 어려우면 성인 동료로 테스트할 수 있다. 이를 실제 학생 수업 효과로 보고하지 않는다.
- 이전 개인 도구를 팀 목적에 맞춰 통합하거나 새로 만드는 것은 기존 초안에서 허용한 방향이다. 최종 제출 규칙과 일치시키고 같은 작품의 중복 제출 기준을 정한다.
- 3차 합류자의 진도·팀 배정을 별도로 점검한다. 서울·부산 본선 날짜가 다르므로 팀의 참가 회차를 수합한다.
- 최종 진출·배점·출석 인정 조건은 교원 연수 이수조건과 구분해 확인한다.

근거: 기존 예선 일정 기록, 8/20 짓다·상호 피드백 방향, 후속 해커톤 기획안의 팀/멘토링/제출 설계. 실행 여부나 승인 완료를 새로 주장한 것은 아니다.
