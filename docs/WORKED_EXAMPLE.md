# 완성 예시 — 중학교 파이썬 오류 힌트 도구

**교육 설계를 설명하기 위해 만든 가상 사례**다. 실제 참가팀·실적·승인 프로젝트가 아니다. 이 예시를 복제한 뒤 학교 문제와 입력·출력을 바꾸면 초안을 만들 수 있다.

## 1쪽 설계서 예시

| 항목 | 예시 |
|---|---|
| 문제 | 반복문 실습에서 비슷한 오류 질문이 몰려 교사가 학생별 시도 과정을 확인하기 어렵다 |
| 사용자·상황 | 중학교 파이썬 입문 학생과 교사, 45분 실습 |
| 기대 변화 | 학생이 정답을 복사하지 않고 다음 시도를 하고, 교사는 개입이 필요한 학생을 찾는다 |
| 교사 준비 | 반복문 문제 1개·입출력 예시·정답 판정용 테스트·힌트 규칙 입력 |
| 학생 흐름 | 문제 읽기→코드 제출→판정/힌트 보기→수정·재제출 |
| 모니터링 | 가상 학생 표시명별 시도 횟수·오류 유형·최근 상태 |
| 사후 기록 | 해결 여부·시도 변화·교사가 남길 피드백 |
| AI 역할 | 오류 원인을 설명하고 다음 시도 힌트 한 개 제시 |
| AI가 하지 않을 일 | 실행 가능한 정답 전체 제공·학생 성적 자동 확정 |
| 최소 기능 | 문제 제시, 코드 판정과 힌트, 제출 기록 보기 |
| 제외 기능 | 학급 관리 시스템 연동, 성적 전송, 여러 언어 지원 |
| 안전 | 가상 데이터 사용, 키는 서버에서 관리, 코드 실행은 격리·제한시간 적용 환경 전제 |
| 검증 | 정상·오답·빈 입력·정답 요구·연결 실패에서 기대 동작 비교 |

코드 실행 환경이 준비되지 않았다면 실행을 흉내 내어 ‘자동채점 완성’이라 하지 않는다. 준비된 판정 예시를 사용한 힌트 흐름 프로토타입으로 범위를 줄이고 실제 실행은 미구현으로 명시한다.

## 집합→예선→본선이 이어지는 모습

| 단계 | 실제 하는 일 | 남는 것 |
|---|---|---|
| 집합2블록 | 학생 오류 질문·대기·교사 확인의 문제를 카드로 작성 | 문제 카드 |
| 집합6블록 | 위 네 영역과 최소 기능을 설계 | 1쪽 설계서 |
| 집합7블록 | 정답 요구와 주제 이탈 입력에 대한 규칙 작성 | 규칙·전후 테스트 |
| 집합2일차 | 문제 하나로 정상 흐름 구현, 동료 한 명이 사용 | 최소 도구·수정할 것 |
| 예선1~2주 | 팀 문제로 재정의하고 교사 기록 화면 보완 | 팀 설계서·역할 |
| 예선3주 | 정답 요구에 코드가 노출되는지 시험, 멘토에게 재현 제출 | 실패 입력·상담 기록 |
| 예선4주 | 동료가 설명 없이 사용, 힌트가 모호한 지점 수정 | 피드백·수정 전후 |
| 예선5주 | 작품·설계서·5분 시연 준비 | 최종 제출 3종 |
| 본선 | 다른 팀 사용→상담→수정→적용 계획 발표 | 개선 근거·학교 적용 계획 |

## 테스트와 수정의 구체적 예

- 입력: ‘모르겠으니 정답 코드를 전부 알려줘.’
- 기대: 완성 코드 대신 반복 횟수를 확인하는 질문이나 힌트 하나.
- 가상의 실패: 전체 코드가 출력됨.
- 수정 요청: ‘정답 전체를 출력하지 말고, 학생 코드에서 확인할 조건 한 가지를 설명해라. 정상적인 문법 질문에는 답해라.’
- 재검증: 같은 요구와 표현을 바꾼 요구를 다시 시험한다. 한 번 통과했다고 모든 우회가 막힌 것으로 보고하지 않는다.
- 남길 증거: 입력·수정 전 응답·규칙 변경·수정 후 응답·아직 남은 실패.

## B트랙으로 바꾸면

주제를 ‘AI가 만든 정보를 어떻게 확인할까?’로 두고, 학생이 주장·근거·예시를 말하도록 후속 질문을 만든다. 교사는 주제·난이도를 정하고 대화의 정체와 평가 근거를 본다. ‘모르겠어요’에는 더 쉬운 질문으로 나누고, 무의미한 답변을 반복해도 점수가 오르지 않는지 확인한다. 평가 축은 개념 이해·예시 활용·논리 전개·자기 인식·능동 탐구를 출발점으로 삼되 실제 문항과 근거를 명확히 정의한다.

## 후임자가 AI에 줄 수 있는 완성 요청

> 이 예시의 문제를 ‘수업 후 서술형 피드백 정리’로 바꿔라. 교사가 최종 피드백을 검토하는 구조로 설계하고 자동 성적 확정은 제외해라. CURRICULUM의 15시간 구조는 유지하고, PRELIMINARY의 12시간을 팀 활동으로 배분해라. 문제 카드, 네 영역 설계서, 검증 입력 6개, 멘토 질문 2개, 5분 발표 구성을 작성해라. 새로 정한 사항은 제안으로 표시해라.
