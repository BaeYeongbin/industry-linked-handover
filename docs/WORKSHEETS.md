## 3. AI에 처음 제작을 요청하는 문장

> [대상 사용자]가 [상황]에서 겪는 [문제]를 줄이는 도구를 만들고 싶다. 첫 버전은 [입력]을 받고 [핵심 처리]를 거쳐 [결과]를 보여주는 한 흐름만 만든다. 교사는 [확인할 정보]를 볼 수 있어야 한다. AI는 [역할]만 하고 [금지 행동]은 하지 않는다. [제외 기능]은 이번에 만들지 않는다. 정상 입력과 빈 입력의 동작을 먼저 만들고 내가 확인할 수 있게 설명해라. 인증키나 실제 학생 정보는 예시에 넣지 마라.

수정 요청은 ‘실제 입력 / 현재 결과 / 원하는 결과 / 그대로 둘 기능’ 네 줄로 작성한다. 안전 규칙은 문장만 추가했다고 완성되는 것이 아니라 테스트로 검증한다.

## 8. 5분 발표 구성 — 편집 제안

문제·대상 40초 → 사용 흐름 시연 100초 → 사용자 피드백 50초 → 개선 전후 60초 → 학교 적용·남은 과제 50초 = 300초.

‘학생 학습이 향상됐다’는 주장은 실제 비교 자료가 있을 때만 쓴다. 동료가 사용한 것을 학생 수업 실적으로 바꾸지 않는다.

## 9. 형성평가표 — 공식 심사표 아님

각 항목을 미확인 / 개선 필요 / 충족으로 표시하고 근거를 한 줄 쓴다. 배점과 합격선은 별도 승인본을 사용한다.

| 항목 | 판단 질문 | 상태·근거 |
|---|---|---|
| 문제·교육적 가치 | 대상과 학습/업무의 개선 목표가 구체적인가 | |
| 작동·사용성 | 의도된 사용자 권한으로 한 흐름을 끝낼 수 있는가 | |
| AI 응답 품질 | 정답/힌트/질문의 역할이 목적과 맞는가 | |
| 안전·한계 | 오류·범위 이탈·정보 노출에 대응하는가 | |
| 피드백 반영 | 수정 전후와 선택 이유가 보이는가 | |
| 적용 가능성 | 학년·단원·시간·기기·계정 계획이 있는가 | |
